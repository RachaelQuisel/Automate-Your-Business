### Snip 1: Agent Autoloop runs Claude Code and Codex in the background and sends you a card when it needs a decision
- Source: GitHub, KKKKhazix/agent-autoloop, README (written in Chinese; translated on fetch)
- Episode/article: "Agent Autoloop: A Self-Hosted Hub That Lets Claude Code and Codex Work in the Background" (brief received November 6, 2026)
- Date: 2026-11-06
- Link: https://github.com/KKKKhazix/agent-autoloop
- Summary: Agent Autoloop is a lightweight automation hub for command-line agents. It lets Claude Code, Codex and other command-line agents pick up jobs in the background and follow them through, and it contacts you only when a decision is unclear. It runs on your own Mac or Linux computer and needs no cloud server and no public port. Requirements are Node 24, Git, curl, and one command-line agent you are already signed in to; Windows is not supported yet, and the README points to WSL2 as a stopgap. Install is one line, `curl -fsSL https://raw.githubusercontent.com/KKKKhazix/agent-autoloop/main/install.sh | sh`. First run is `agent-autoloop try`: the agent asks a question, exits, and uses no process and no tokens while it waits; you answer by typing a number, or with `agent-autoloop answer 1 <number>`, and `agent-autoloop status` shows the agent resume and finish, plus rounds, tokens and cost for today and the last seven days. Jobs are rules in `~/.agent-autoloop/rules.json`, each with a trigger (`when`), an agent (`to`), a working folder (`cwd`), and a prompt; the README's example is a morning brief on `"cron": "0 9 * * *"`, and a second rule routes `issues.opened` events from GitHub to a skill with up to three in parallel. Saved rules take effect within seconds, and if the file breaks, the hub keeps the old rules and sends you a card. The agent asks by ending its final reply with an `agent-autoloop` block whose `ask` list carries a title, text, options and a key. `agent-autoloop check` verifies the configuration, `rules explain` lists the active rules and their next run times, `emit <type> --dry-run` previews which agent an event would reach without touching the hub, and `agent-autoloop why 1` traces one round from trigger to outcome. Cards reach you by desktop notification by default, or by Feishu, DingTalk, WeCom, Slack or Discord. For high-frequency automation the README says vendors generally recommend an API key rather than a personal subscription. The project is independent and states it has no affiliation with Anthropic or OpenAI. MIT license; 3.4k stars and 621 forks on November 6, 2026.
- Loop/workflow angle: the shape every small business background job needs, in one tool: a trigger, a named worker, one folder, one job sentence, and a card that stops the clock until a person decides. Today's workshop pick, paired with Snip 2.

### Snip 2: The project's own SECURITY.md says what the hub does and does not protect
- Source: GitHub, KKKKhazix/agent-autoloop, SECURITY.md (written in Chinese; translated on fetch)
- Episode/article: "SECURITY.md"
- Date: 2026-11-06
- Link: https://github.com/KKKKhazix/agent-autoloop/blob/main/SECURITY.md
- Summary: The security page is short and unusually direct. Rules decide everything: only `rules.json` chooses the agent, the working folder, the skill and the permissions, and an incoming event that tries to carry `cwd`, `agent` or `access` is rejected. The default permission is `edit`; the page says to think about everything the agent can reach before granting `full`, and to route actions with side effects through `askFirst`. Prompt injection is not solved: titles and bodies written by other people, such as a GitHub issue, are placed in files labeled as data rather than in the prompt, and the page says plainly that this does not block all prompt injection, because the agent still reads the text. A read permission still reads secrets: a normal agent's `read` does not stop it reading keys stored on the machine, so the page suggests a separate operating-system account or a container. The hub listens only on localhost by default; for outside access, put an HTTPS reverse proxy in front. Approval links are bearer links: anyone holding a card link can answer that card, links last seven days from the card's creation, and they should never be posted publicly. Credentials stay with the agent CLI: the hub launches the tools you already signed in to and says it does not access, store or relay their credentials; ordinary access keys are stored only as SHA-256 hashes, and a local `master.key` derives round and card-link tokens. Webhook authentication is not described: the page covers webhook idempotency, warning that a send that succeeds without its report arriving can cause a duplicate, and says nothing about signature checks on incoming webhooks. Known limits: crash-safety tests cover process kills and a finite set of scenarios, nightly checks SIGKILL a real SQLite process, and the page says this is not a power-loss proof and not a full security audit. ACP authorization depends on the agent honoring the protocol, since the spec allows an agent to act without asking. Backups contain the master key and `secrets.env` and must be guarded like keys.
- Loop/workflow angle: the five fences for any unattended agent, written by the people who built one: rules outside the message, edit by default, ask-first for side effects, secrets in a separate account, and a card link treated like a house key.

### Snip 3: What the one-line installer actually does, read before running
- Source: GitHub, KKKKhazix/agent-autoloop, install.sh (read in full on November 6)
- Episode/article: "install.sh"
- Date: 2026-11-06
- Link: https://github.com/KKKKhazix/agent-autoloop/blob/main/install.sh
- Summary: The installer is a plain shell script that stops on the first error. It checks for Git and Node 24 or newer, and if Node is missing it prints Homebrew or nvm instructions and exits without running them. It creates `~/.agent-autoloop` with owner-only permissions, picks the highest `vX.Y.Z` release tag, and shallow-clones the repository into `~/.agent-autoloop/app`, or fast-forwards an existing clone. It places a symlink named `agent-autoloop` in `~/.local/bin` or the first writable folder already on your PATH, and refuses to overwrite anything there that is not its own symlink. It never calls sudo and never edits your shell profile. On a fresh install it runs the program's `init`; on an update it runs `service install` unless you pass `--no-service`, which means a background service is set up for you. There are no checksum or signature checks; trust rests on HTTPS access to GitHub and the tag selection.
- Loop/workflow angle: a one-line install is a trust decision, same as a skill. This one is readable in five minutes, uses no administrator rights, and installs a background service, which is the part to know about before you run it.
