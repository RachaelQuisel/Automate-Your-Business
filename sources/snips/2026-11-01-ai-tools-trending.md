### Snip 1: Salesforce gives agents live tests, hard spending caps, and a kill switch
- Source: Elets CIO, reporting Salesforce's November 1 announcement
- Episode/article: "Salesforce Gives CIOs a Kill Switch for AI Agents, Adds Live Evals and Hard Spending Caps to Agent Fabric"
- Date: 2026-11-01
- Link: https://cio.eletsonline.com/artificial-intelligence/salesforce-agent-fabric-agent-evals-kill-switch-ai-agent-governance-cost-controls/76624/
- Summary: Salesforce added continuous testing, automatic intervention, and hard spending caps to Agent Fabric, its control plane for managing agents across platforms, announced November 1, 2026. Agent Evals generates tests before an agent goes live and keeps scoring it against quality thresholds once it is running; when an agent falls short, the system can trigger a pre-agreed response up to pulling the agent offline through an Agent Kill Switch, with a human sign-off where policy requires one. This is today's workshop pick.
- Loop/workflow angle: a complete running-agent workflow. Test before launch, keep testing on live work, cap the spend in money, agree in advance what happens when a test fails, and make the off switch one named action owned by a named person.

### Snip 2: Vercel Labs open-sources agent-desktop, computer use from structure, not screenshots
- Source: ShiftDelete and CryptoNWZ, reporting the October 31 Vercel Labs announcement
- Episode/article: "Vercel Labs Open-Sources agent-desktop for Agent Computer Use"
- Date: 2026-10-31
- Link: https://cryptonwz.com/vercel-labs-open-sources-agent-desktop-for-agent-computer-use/
- Summary: Vercel Labs released agent-desktop, an open-source tool that lets AI agents operate native desktop applications on macOS, Windows, and Linux, announced October 31, 2026 by Chris Tate, who called it agent-browser for your whole computer. Most computer-use systems take screenshots and ask a vision model to guess where buttons are. Agent-desktop instead reads the operating system's accessibility tree, the structure screen readers use, through the AX API on macOS, UI Automation on Windows, and AT-SPI on Linux, and hands the agent a structured snapshot with a reference for every element it can act on. The agent clicks or types through that reference, then takes a new snapshot to confirm the change. It is not an agent itself: it ships no language model, so it works with Claude Code, Codex, or any agent that can run shell commands, and it runs in the background with each agent getting its own cursor. Version 1.0.2 shipped October 30, 2026 under Apache-2.0. The builder reported token cuts of 78 to 96 percent versus full-tree dumps in apps like Slack, VS Code, and Notion; those figures are self-reported, not an independent benchmark. It cannot see apps that do not expose an accessibility tree, and it does not automate web pages.
- Loop/workflow angle: observe, act, verify, in a loop a business can actually audit. The snapshot before and the snapshot after are the record, and a reference that stays stable makes an action safe to retry instead of a pixel guess that breaks when a window moves.

### Snip 7: Gemini Spark has become Task, and a task, a schedule, and a skill are three different things
- Source: Omid Saffari, guide built from Google's help documentation, checked November 2026
- Episode/article: "Gemini Spark: Tasks, Connected Apps and Business Limits"
- Date: 2026-11-01
- Link: https://omidsaffari.com/blog/gemini-spark
- Summary: Google's Gemini Spark has become Task inside the Gemini app; Google's help page explains the rename and says existing work remains available in the sidebar. The guide's useful separation, drawn from Google's own documentation, is three parts: the task defines the outcome, the schedule determines when work starts, and a skill supplies reusable instructions, so for a recurring supplier brief the task is preparing the brief, the schedule is the agreed weekday, and the skill holds your source standards and report format. The limits matter as much as the pitch. Task requires a personal Google account for a person aged 18 or over, with Keep Activity enabled and an opt-in to personalisation; managed work and school accounts are excluded, Google AI Pro and Ultra are the listed plans, and availability excludes the European Economic Area, Nigeria, Switzerland, and the United Kingdom. The workflows in the guide are proposed examples, not results from a signed-in test.
- Loop/workflow angle: outcome, timing, and house rules, written separately, is the cleanest description yet of a recurring agent job. Repeating an unclear assignment simply produces unclear work more regularly, which is why the skill, the standing instructions, gets fixed before the schedule is trusted.

### Workshop pick: Snip 1, Salesforce gives agents live tests, hard spending caps, and a kill switch
The richest end-to-end workflow in today's file is the running-agent safety workflow inside Salesforce's Agent Fabric announcement, because it answers the question yesterday's interview habit cannot: what do you do after the agent is live and quietly goes wrong. The workflow is complete and can be run on paper by any small business, with no Salesforce purchase. Write five tests from real past jobs, with the right answer written down before the agent ever sees them. Run the tests before any change goes live, and keep running a small set on live work every week. Give the job a spending limit in money, not tokens, and a rule that stops requests when the limit is reached. Agree in advance, in writing, what happens when a test fails: who is told, who can pull the agent offline, and what has to pass before it goes back. The workshop is called Give Your Agent a Test, a Spending Limit, and an Off Switch. It carries today's other stories with it: the snapshot-before-and-after record from agent-desktop (Snip 2), the per-cell source check in Sheets (Snip 5), and the deadline inventory from the evals and fast-mode retirements (Snip 11).
