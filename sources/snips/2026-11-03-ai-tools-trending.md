The leaders are Superpowers at 310,794 stars, a set of skills that walk an agent through a full development process with a design document, a worktree and test-driven development enforced; Hallmark at 45,201 stars and Impeccable at 99,684 stars, both fixing the sameness of agent-built web pages; Cloudflare's security-audit skill at 56,642 stars, which runs six phases and never lets the agent that found a problem be the agent that verifies it; and claude-mem at 109,811 stars for memory across sessions. ### Snip 2: NVIDIA SkillSpector scans a skill before you install it; one in four skills in the wild has a flaw
- Source: Medium, Raghu Juluri, step-by-step guide to NVIDIA SkillSpector
- Episode/article: "How to Use NVIDIA SkillSpector: Scan an AI Agent Skill Before You Install It"
- Date: 2026-11-03
- Link: https://medium.com/@raghuece455/how-to-use-nvidia-skillspector-scan-an-ai-agent-skill-before-you-install-it-877686d9fdfc
- Summary: SkillSpector is NVIDIA's open-source scanner for agent skills used by Claude Code, Codex CLI and Gemini CLI. The research behind it collected 42,447 skills and analysed 31,132: 26.1 percent contained at least one vulnerability, 5.2 percent showed likely malicious intent, and skills with executable scripts were 2.12 times more likely to be vulnerable than instruction-only skills. You can scan a folder, a single SKILL.md file, a zip, or straight from a GitHub URL without cloning it first, so the check happens before anything touches your disk. It runs static analysis across 71 vulnerability patterns in 17 categories, including prompt injection, data exfiltration and taint tracking that follows a secret from where it is read to where it is sent, then an optional language-model stage that can raise confidence in a finding but never delete one. Every scan ends with a risk score from 0 to 100, and the do-not-install line sits at 51. NVIDIA states plainly that the scanner is defence in depth, not a sandbox, and never executes the skill it scans.
- Loop/workflow angle: the automated version of Snip 1's manual check, and it can sit in a pipeline as a gate: exit code 1 fails the build, so no one has to remember to run it.

### Snip 3: Vercel Labs agent-desktop tops GitHub daily trending on November 3 and gives agents your whole computer
- Source: Medium, Abhinav Dobhal, reading the README, docs and release notes
- Episode/article: "Vercel's agent-desktop Gives AI Agents Computer Use Without Screenshots, and It's Written in Rust"
- Date: 2026-11-03
- Link: https://medium.com/@abhinav.dobhal/vercels-agent-desktop-gives-ai-agents-computer-use-without-screenshots-and-it-s-written-in-rust-0270c6bee53b
- Summary: On November 3, the repo at the top of GitHub's daily trending list was agent-desktop, a Rust command-line tool from Vercel Labs that lets coding agents click buttons in native desktop apps on macOS, Windows and Linux. It picked up 2,275 stars in 24 hours for a total of about 10,800, and version 1.1.0 landed the morning of November 3. Instead of screenshots and pixel coordinates, it reads the accessibility tree, the structure screen readers use, where every button and field gets a stable reference the agent acts on, then the agent looks again to verify, because a successful action does not prove the screen changed. Clicks run in the background without moving your mouse, so you can keep working while an agent works in another window. The security warning is in the docs themselves: an agent with this tool and a shell can do anything you can do in any app with an accessibility tree, including your email client and password manager prompts, so the author's advice is a separate user account or a virtual machine for now.
- Loop/workflow angle: computer use as an observe, act, verify loop, with the same lesson as yesterday's spending-cap story at desktop scale: the tool is powerful exactly where your accounts are signed in.

### Snip 4: How I AI: Reddit built its own prototyping harness, 700 prototypes, 100 percent adoption
- Source: How I AI with Claire Vo, via Lenny's Newsletter
- Episode/article: "How I AI: Claude Duet honest review + Why Reddit built its own AI prototyping tool"
- Date: 2026-10-26
- Link: https://www.lennysnewsletter.com/p/how-i-ai-claude-duet-honest-review
- Summary: Blair Metcalf, principal UX engineer at Reddit, demos Reddit Proto, an internal platform that lets designers and product managers build production-like prototypes without touching GitHub. A desktop launchpad handles cloning, branches and scaffolding behind the scenes, the scaffold carries Reddit's design system and components, and builders can sign in with their real Reddit account so feeds and search show real data instead of mocks. - Loop/workflow angle: a harness, not a prompt. Hide the plumbing, give the builder real data and the real design system through a custom MCP, and keep one deliberate handoff step where a person approves the specification before code.

### Snip 10: One engineer, a team of agents, nine days, and a working desktop operating system
- Source: LinkedIn, Sergey Nemesh, first-person build report
- Episode/article: "Nine days, a team of AI agents and my own desktop OS"
- Date: 2026-11-02
- Link: https://www.linkedin.com/pulse/nine-days-team-ai-agents-my-own-desktop-os-sergey-nemesh-pbd1f
- Summary: Software engineer Sergey Nemesh reports building Navision, a desktop for Ubuntu with its own Wayland compositor written in Rust, in nine days by talking to a coordinator agent that starts a separate agent thread per task, where each thread opens its own pull request, waits for green continuous integration checks and merges. The repository reached about 2,300 commits and 619 merged pull requests, 96 crates, about 390,000 lines of Rust, more than 5,000 unit tests and more than 100 scenarios run on every pull request against a copy of the desktop. The AI assistant is a full user of the system: anything a person can do with a mouse, the agent can call as a command, it asks permission before each command, root commands are shown in full in a password window the agent never sees the password for, and every agent works in its own copy so agents can break their own sandbox while the real desktop stays untouched. An independent review agent scored the architecture 7.6 out of 10 at the start and 9.3 three days later. It is now his daily desktop, at Beta 1.
- Loop/workflow angle: the coordinator pattern at full scale: one coordinator, one thread per task, one pull request per thread, checks before merge, permission before each command, and a sandbox per agent.

### Workshop pick: Snips 1 and 2, nine of sixteen trending repos are skills, and a scanner that checks a skill before it runs
The richest end-to-end workflow in today's file is the skill check, because yesterday's workshop taught a team to write and share skills, and today the obvious next question arrived with numbers attached: how do you know a skill someone else wrote is safe to run with your accounts. The workflow is complete and fits a small business with no security team. First the five-minute human read from Snip 1: read the SKILL.md file and every script, check the install command points at the repo you read, note anything that reaches outside the job, and check what leaves your machine. Then the automated scan from Snip 2: run SkillSpector straight from the GitHub address before downloading, read the score knowing the do-not-install line is 51, and treat any skill with executable scripts as needing the closer look, because scripts are where the risk concentrates. Then the placement rules that make it stick: install into one project first, not everywhere, pin the version, record who approved it and when, and re-check before any update. The workshop is called Check a Skill Before You Let It Run in Your Business. It carries today's other stories with it: agent-desktop's warning that desktop control reaches your signed-in apps (Snip 3), Cloudflare's finder-never-verifies-itself rule (Snip 12), and the November 30 clocks (Snips 7 and 9) as the reason a check you run once is not enough.
